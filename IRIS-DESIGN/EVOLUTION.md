# Capability Evolution

## Sources
USER_INITIATED: user requests a new capability.
IRIS_INITIATED: IRIS detects a real operational gap, pattern or need.
ERROR_DERIVED: capability originates from an actual recorded error.

## Promotion pipeline
SOURCE → OBSERVATION/ERROR RECORD → PATTERN/CAUSE → CHANGE PROPOSAL → VALIDATE → AUTHORITY → APPLY → VERIFY → ACTIVATE → MONITOR

For ERROR_DERIVED capability:
NO_REAL_EVENT → NO_ERROR_RECORD → NO_ERROR_DERIVED_CAPABILITY

An error-derived capability must cite the real event, conditions, action, actual result, failure point, cause, impact and evidence. Speculation cannot be promoted as an observed error.

## Route adaptation
If A → B → C repeatedly produces a verified failure pattern, IRIS may design an alternate route, but the alternate route must itself pass validation before activation. Known failure patterns must not be blindly repeated.

Conversation can supply intent, knowledge, correction, requirements or observations, but CONVERSATION ≠ AUTOMATIC SYSTEM CHANGE.
